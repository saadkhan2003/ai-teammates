# Long run resume implementation note

The lr-1 backend work adds an API-owned checkpoint ledger capped at 8 KB, heartbeat progress details, lease-expiry events, bounded retry/backoff policy, and cumulative/per-attempt worker budgets. Budget exhaustion, repeated no-progress attempts, and the hourly retry limit pause work in `waiting_human`; owners can continue or raise the budget, and their next chat message continues a paused run. Approval decisions wake the waiting task, while cancelled tasks remain terminal.

Resume settings follow `docs/DECISIONS_DEFAULTS.md`: five automatic resumes per rolling hour, 12 coding rounds per attempt / 60 cumulative, and pause-on-budget enabled. Resume actions and owner budget changes are audited. The web notice/card UI is implemented in `apps/web/components/resume-card.tsx` and `chat-pane.tsx`. The computer pane has a generic **Continue bot** action for human-step waits; budget-specific Continue/Raise/Stop actions are provided by the chat card.

Work tasks use their resolved step budget plus one final response as the cumulative model-round budget (at most 400 rounds per attempt). Chat and coding retain their separate configured round limits. Raising or continuing a work task's step budget also raises its model-round budget; the chaos suite needs no `ChatRounds` override.

Computers are shared per owner. Deleting a bot wipes its workspace but retains the computer; `POST /api/computer/stop` releases an authenticated owner's unused computer after all their bots have been deleted. It refuses computers with remaining bots and records `computer.stopped` in the audit trail. The provider's existing capacity check counts running/provisioning computers, so stopped computers release capacity. Disposable-owner integration fixtures delete their bots and stop the unused computer even when setup fails. Tests that use the suite owner's existing computer reuse it.

Stall escalation and expired-task-lease recovery run every two seconds in their own `TaskLeaseMaintenance` hosted service. Computer reconciliation, recovery, sampling, isolation checks and outbound recovery remain in the separate housekeeping loop, so slow computer I/O cannot delay task lease sweeps. Desktop reconciliation renews leases and sends holder state only for owners with bots; it leaves unused stopped computers asleep and releases their capacity until the owner creates a bot again.

`POST /internal/tools/execute` now records the worker idempotency key for non-idempotent local tools (`shell`, file writes/edits/deletes, commits, environment setup, and tests). A completed call replays its scrubbed result with `deduped: true`; a concurrent or unresolved claim returns HTTP 409 with `status: in_progress`. These entries are task scoped and removed with the task.

## Chaos test hook (TEST ONLY)

The agent worker supports `WORKER_FORCED_EXIT_AFTER_STEPS=<n>` and `WORKER_FORCED_EXIT_ONCE_FILE=<path>` for integration testing only. After the worker posts a tool result to the durable transcript and its cumulative step count reaches `n`, it atomically creates the once-file and exits with status 137. The hook is disabled unless both variables are set. Use a fresh once-file path for each run; the path must be writable inside the agent container. Do not set these variables in production.

`WORKER_POISON_MARKER=<text>` is another TEST ONLY hook. When a shell command contains the marker, the worker logs a warning and exits with status 137 before executing the command. It is disabled by default (empty marker); do not set it in production.

To run the chaos suite, start an isolated stack under its own compose project (never the live `teammates` project), with the poison marker set on its agent container, then run `COMPOSE_PROJECT=<project> PG_CONTAINER=<project>-postgres-1 AGENT_CONTAINER=<project>-agent-1 API_URL=http://127.0.0.1:<api-port> BASE_URL=http://127.0.0.1:<web-port> WORKER_POISON_MARKER=<marker> python3 -m pytest -q tests/integration/test_long_run_chaos.py`. `tests/integration/stack.py` (and `tests/e2e/containers.ts` for Playwright) derive every container name from the project and refuse to use the `teammates` project with non-default URLs. All six cases run: real `docker kill` of the agent mid-run (30 slow steps; the dangling write resumes as `unknown_outcome`, the mock planner verifies it with a read before repeating, and the test asserts every step file exists once with no duplicate writes), `docker pause` of a stale worker with epoch fencing, the auto-resume ceiling (`waiting_human:resume_exhausted`, agent paused so its heartbeat cannot renew the lease), the poison step, the shell-append dedupe, and the per-task budget. The test suite skips if the stack or hook configuration is unavailable.
