# v0.4 summary

Branch `v0.4-codex`, based on v0.3 (`0a8a3fa`). See CHANGELOG.md for the full list.

- **UI**: dark shadcn shell modelled on the Grok Bot layout (own name, logo and colours): sidebar with bots, chat, info pane, Settings modal, command palette and keyboard shortcuts (Settings > account menu > Support > Keyboard shortcuts).
- **Create New Bot**: modal with live avatar preview, name-only form, 15 avatar shapes and colour swatches (migration 014 adds `avatar_shape`/`avatar_color`).
- **Grounded answers**: replies cite what the teammate actually saw/did; failures show readable errors; tasks in `waiting_resource` resume after the key is saved; failed steps auto-retry.
- **Settings > Computer**: device registration (v0.3 companion) next to the per-bot computer settings.
- **Computer image**: Node and uv preinstalled, a second display per bot, `/workspace` path mapping, DNS through TEAMS-ISO only.
- **Banner and seeding**: an empty-key banner appears until an OpenRouter key is saved; the installer seeds a key from the environment if present.
- **Browser tab cap**: the shared per-user computer closes the oldest Chromium tabs beyond `COMPUTER_MAX_TABS` (default 8, min 2), so 4 GB hosts do not run out of memory.

Security is unchanged: PolicyGate, DLP, TEAMS-ISO and per-bot workspace privacy are still authoritative.

## Chat and panel features (chunks 7–9 plus steering items)

- **Animated bot icon.** Six-lobed blob (and the other shapes) morphs with SVG path interpolation and CSS transforms from one shared rAF clock (`lib/avatar-motion.ts`), so the sidebar card, chat header and typing row stay in sync. Idle loop is about 8.5 s (breathing, squash and elastic bounce, wobble with eye parallax). Working/typing speeds up the lobe undulation and turns the eyes into darting circles. `prefers-reduced-motion` freezes it.
- **Working row.** One row per working bot in the chat: that bot's avatar (own shape and colour) plus "Typing…" while it writes a reply, else the current step or task title, with a left-to-right shimmer (~2 s, off under reduced motion).
- **Add to chat.** Selecting text shows a floating "Add to chat" button; the composer holds ordered quote and text parts. Sent bubbles show quotes dimmed with a left border and a Show more/less clamp. Stored as `metadata.parts`, with flattened `> ` content. The bot receives quotes as fenced context (fence longer than any backtick run inside the quote). Limits: text 8,000, at most 10 quote/reply blocks, quote 4,000 each and 12,000 total; DLP applies.
- **Message actions.** Hover toolbar (React, Reply, "..." menu with Copy, Copy request ID, Retry, Remember this, Delete), long-press sheet on touch, keyboard shortcuts. Works on your own messages too. Delete is a soft delete with confirm (409 while its task runs or a question is open). Retry makes a new task (409 while running, 429 within 5 s).
- **Composer.** Placeholder follows the bot ("Message <name>"); round "+" menu attaches files or inserts a quote.
- **Right panel.** Closes with X, reopens from the bot-name pill (small animated avatar and name) in the chat header; state per user in localStorage; `aria-expanded`; Enter/Space toggle; Esc closes.
- **Primary bot star.** The first-created bot gets an orange star badge (bottom-right of the avatar) in the sidebar, header pill and panel; `aria-label` "Primary bot" plus tooltip; `bots.is_primary` (migration 017). Deleting the primary promotes the earliest remaining bot.
- **Bio.** `bots.bio` (migration 018, at most 60 chars): grey text under the name in the panel, a chip on the sidebar card, optional in Create New Bot, inline editable and saved on blur. A bot setting its own bio (`update_bot`) is deferred with bot messaging.
- **Computer tab.** Rounded live thumbnail captioned "<name>'s screen" (calm placeholder when stopped). Clicking opens the full computer view: dark page, rounded frame, collapse/restore, minimise, close, true full-screen versus compact toggle, Esc exits. VNC input and focus keep working in both.
- **Take control.** Clean frame, your keyboard and mouse go to the desktop, the bot is paused by the control lock (its task is not cancelled), Stop hands back and the bot resumes. The preview shows a "You're in control" chip. Bottom pill reads "You're in control" with Stop.
- **Library tab.** Files and artifacts grouped by day, thumbnail rows, age, "..." menu, "Show more", hover preview card.
- **Share menu.** "Create a copy" (new bot with persona, avatar and routines disabled; no secrets, memory, files or plugin config) and "Share a template link" (versioned JSON template, DLP-checked, 8 KB cap, carried in the link and never stored). Create New Bot can import a template link or JSON; the server validates it before it fills the form.
- **Teach a task.** Computer tab > "Teach a task" opens the full view and takes control. A banner reads "<name> is watching and learning" with a red timer chip and an X (discard); the desktop frame gets a red outline; the bottom pill says "You're in control" with Stop. The desktop canvas is recorded in the browser (MediaRecorder, webm). A blank or idle recording (nothing visible, or nothing changed) is not sent. On Stop the recording is uploaded to `/workspace/recordings/`, and "The recording is finished. Learn the task from it." is posted as you, with a "Learn from demonstration" chip and the recording attached. That starts a task: watch the recording, extract steps, write a reusable skill draft, delete the raw video.
- **Worker concurrency.** `WORKER_PARALLEL_TASKS` defaults to 4 and can be raised to 8 (hard cap).

### Per-bot accent colour: where it applies

The bot's avatar colour drives CSS variables (`--bot-accent*`, plus `--primary`, `--ring`, `--user-bubble`, `--brand`), with a computed readable foreground (and a lightened/darkened fill for mid-tone swatches so text on it keeps at least 4.5:1). A unit test audits all 14 swatches. Places that follow it:

1. Your sent message bubbles (and their text colour).
2. The Send button and other primary buttons (`bg-primary`).
3. The composer focus ring and all focus rings (`ring`).
4. Active tab indicator in the right panel and tab focus ring.
5. Switches in Settings and the panel (checked state).
6. Brand-coloured text (logo mark, links styled `text-brand`).
7. Selected quick-reaction pills and the active emoji cell hover.
8. The "Add to chat" pill and quote accents in the composer.
9. The "+" menu focus and active states.
10. The right panel: header identity, tab underline, take-control ring, "You're in control" ring.
11. The sidebar: active bot card ring and the bio chip border.
12. The typing/working row shimmer tint and status text.
13. Sidebar `sidebar-ring` focus.

Not accent-driven on purpose: destructive actions (red), the recording indicator (red), the primary star (orange), status colours.

## Loading and motion

### Skeleton loading
Every list or pane that waits on the API shows a skeleton with `role="status"`, `aria-busy` and an sr-only label, and gives way to content with a short fade: sidebar roster (`sidebar-skeleton`), chat workspace (`chat-skeleton`), routines, Library (`library-loading`), plugins, system, usage, secrets and the lazily loaded Computer tab. "No teammates yet" only appears once the roster has loaded.

### Motion tokens
`app/globals.css` defines `--motion-fast` 150ms, `--motion-base` 200ms, `--motion-slow` 250ms and easings `--ease-out`, `--ease-in-out`, `--ease-spring`; `tailwind.config.ts` maps them to `duration-fast|base|slow` and `ease-out|spring`. Utilities: `motion-rise` (fade and slide up), `motion-fade` (skeleton to content), `motion-pop` (fade and scale), `motion-card`, `motion-clamp`.
Applied to: dialogs, sheets, dropdowns, context menus, popovers, tooltips and toasts (fade and scale or slide, from the shadcn animate classes, durations on the tokens); right panel slide; tab triggers and tab content; button hover and press (scale .97); cards; sidebar bot cards (hover, press, selection) and collapsible sections (height); messages that arrive live (history does not animate); quote and long-message Show more/less (max-height); approval cards; library groups and rows; the full computer view (opens with fade and scale; closing is instant); skeleton to content.
`prefers-reduced-motion: reduce` forces near-zero durations, no transforms on hover/press, and the shimmer stops. Only opacity and transform are animated on elements that tests click.
